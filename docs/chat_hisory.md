We just opened up Project Gold!

What you'll do:

You'll connect one of your own private codebases and author an original, coding task on it which would be a clear, maintainer-style issue, a hidden test suite (fail-to-pass + pass-to-pass), and a reference solution. Every submission is validated automatically before approval.
How it's checked:

Each task runs through automated validation: your reference solution must pass every test, an untouched repo must fail them, and the task has to land in the difficulty sweet spot of being solvable but genuinely hard. You'll have up to 5 attempts to get a task through the checks, so take your time and don't rush it.
Pay:

How to start:
Go to experts.afterquery.com/projects/gold
Before you can access tasks, make sure you've completed:
• NDA
• Data submission form
• Connected a private GitHub repo
Let us know if you have any questions!

Hi everyone! We've gotten a few questions about what makes a great repo for this project, so we wanted to share some friendly guidance.

The repos that shine here are projects you built for yourself at some point, with their own story, their own history, and plenty going on beyond the tasks you create on them. That authenticity is exactly what makes this project special, and it's what we're paying for.

On that note, a gentle but important heads up: repos that are generated for the occasion, given an artificial git history, or built as thin shells around tasks unfortunately can't be accepted. We'd hate to remove anyone over this, so when in doubt, just ask!

If you're ever unsure whether a repo is a good fit, feel free to DM and we'll happily take a look before you invest time in tasks.

Thanks for everything you all do! 🙌

One more update on repo eligibility 🙏

Hi everyone, following up on the repo guidance from earlier with one important clarification.

Going forward, we can only accept codebases that were already on GitHub before this project started. Anything developed locally that wasn't on GitHub before this unfortunately won't qualify for Project Gold right now. This also means a fresh upload of an older local project won't meet the bar, no matter how real the project is, so please don't push old code up now hoping it will qualify.

We know this is a big change to the platform and many of you have real, legitimate projects that have only ever lived on your own machine, and we're not questioning that code at all. The honest reason for this rule is that prior GitHub history is currently the most reliable way for us to verify a repo is authentic, and holding that line is what lets us keep the quality bar (and the pay that comes with it) where it is for everyone.

If this rule leaves you without an eligible repo, you haven't lost your spot. Hang tight, we're actively looking on options for exactly this situation. If we find a good way to open this up, we will absolutely update you, and we'll keep you posted either way.

Thanks so much for understanding!
