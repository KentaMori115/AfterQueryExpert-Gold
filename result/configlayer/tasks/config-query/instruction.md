Layer policies select keys with dotted-glob patterns, but nothing runs them over a config tree, so every secrets sweep hand-rolls a walk. Add a `configlayer.query` package over the pattern language of `configlayer.policy.KeyPattern` (`*` one segment, `**` any run including none, anything else literal). An invalid pattern raises the same `ConfigError` it always did, as does a config that is not a mapping.

`select(config, patterns)` takes a nested mapping and one pattern or an iterable, returning a list of frozen `Match` records, the dotted path string in `path`, the node in `value`. Results follow the tree depth first in each mapping's key order, whatever order the patterns arrived. A pattern hitting an interior mapping yields that subtree as one record, nothing beneath it; `**` may match nothing, so `db.**` also covers `db`. No node appears twice. `first(config, patterns, default=None)` returns the first match's value or `default`; `paths` and `values` return lists of the matched paths and values. `pick` copies the selected nodes keeping nesting and key order, parents only where something survives beneath; `prune` returns the complement, so a mapping whose children were all selected survives empty. Neither mutates nor aliases the input. A `Query` compiles a pattern set once (strings or `KeyPattern` objects, empty set refused) and offers the same operations as methods, answering as they do, plus a boolean `matches(config)`.

`select_origins(layered_config, patterns)` queries a stack's resolved view but reports leaves, a list of frozen `OriginMatch` records (`path`, `value`, `origin`): an interior hit expands to the leaves under it, each naming its supplying layer, disabled layers honoured. Re-export `select`, `pick`, `prune` at package top level; note the work in `CHANGELOG.md`.
