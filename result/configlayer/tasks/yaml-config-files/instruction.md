Our services keep drifting toward YAML for their config files, and configlayer still cannot read them. Add YAML support in the same spirit as the existing INI and minimal-TOML support: a hand-written parser for a small, unambiguous subset, zero third-party dependencies.

Add a `YAMLLoader` to `configlayer.loader` (exported like the other loaders, subclassing the `Loader` base) that parses block mappings and block sequences nested by indentation (spaces only — a tab in indentation is an error), one-line flow collections `[a, b]` and `{k: v}` including nesting, compact `- key: value` entries whose later keys align with the first, and `#` comments at line start or after whitespace but never inside quotes. Bare scalars coerce exactly as follows: lowercase `true`/`false`, and `null`/`~`/empty meaning None; plain base-10 integers; decimal floats with optional exponent; everything else — including `True`, `inf`, `1_000` — stays a string. Double-quoted strings honour the `\n`, `\t`, `\r`, `\"`, `\\`, `\0` escapes; single-quoted strings are literal with `''` as the only escape. Anchors, aliases, tags, block scalars (`|`, `>`), document markers, multi-line flow collections, duplicate keys and unknown escapes are refused with `LoaderError` messages naming the offending construct and its 1-based line number. The document root must be a mapping. The loader registry and its format list must not change.

`FileSource` should treat `.yaml`/`.yml` files (any case) as a new `yaml` format, also selectable through `format="yaml"`, wrapping parse failures in `SourceError` as "Invalid YAML in <path>" with the loader error chained as the cause. Record the addition in `CHANGELOG.md`.
